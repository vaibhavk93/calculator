Look at `dark-00-calculator.png`. One bare number, 52px, weight 300. The expression above it is quiet. Sixteen keys
all one size. Three small icon buttons for follow-up actions. Nothing else on the page asks for attention.

```

 Budget hero          32px / 500 bare           dark-10-budget
```

Each other screen picks a different size for "the number", and most box it. That is the main reason they feel unlike the calculator.

## Research: how others solve the same screens

Marks: **P** primary source, **S** secondary (review or news), **I** my inference.

| Pattern | Source | Fits this app? |
|---|---|---|
| Don't hide key actions behind swipe. Limit swipe to destructive actions. Keep a salient undo | NN/g "Contextual swipe" (**P**) | **Yes.** Due should show one visible action. Swipe may only add Remove, with the Undo bar the app already has |
| Cards suit mixed content and browsing. They hurt for homogeneous items, comparing, scanning and small screens | NN/g "Cards" (**P**) | **Partly.** Tools home is browsing, so tiles are defensible. But 8 same-type items and 360px argue for a list. Rule wins |
| Settings: keep only infrequent preferences. No app info or version in settings. 15+ settings go to sub-screens. Don't use "Set, Change, Manage, Use". Show status, don't describe it | Android Developers, Settings pattern (**P**) | **Yes.** Backs B17 |
| Navigation bar holds 3 to 5 destinations of equal importance, keep labels | Material 3 navigation bar (**P**) | Already met (5). Do not add a centre "+" tab |
| Extra fields stay hidden until needed. One "+" to add. Today merges events and to-dos in one view | Things 3 features page (**P**, vendor) | **Yes.** Backs B12 and B15. Merging Due into To-do is a bigger choice, see (e3) |
| Raised "+" in the middle of the tab bar as the one add action | Spendee review (**S**) | **No.** Makes a 6th control in a 5-tab bar |
| Lower-frequency tools tucked under "More" so daily tasks stay short | CRED redesign write-up (**S**) | **Yes** as a model for Settings and Budget's tier 3 |
| Google Tasks cards (2024); iOS inset-grouped sections | 9to5Google (**S**); Apple docs (**P**, old) | **Rule wins.** Hairline groups are the app's rule and shipped |

**Not found:** Material 3's list-density page and Apple's current list guidance returned only a title, and I found no primary
source on icon-only labels, so that point is **inference** from the app's own DS 14.5.

**Popular patterns the rules forbid:** elevated cards, shadowed FABs, gradient heroes, dynamic colour, pie and ring charts,
inset grouped sections. The rule should win each time: the owner's complaint is "a lot of list, a lot of card", and the
calculator they like already follows the rules.

## (d) Do NOT do

- **No new card, tint or shadow** anywhere to "make it pop". The owner's complaint is the opposite.
- **No centre "+" tab or FAB** in the tab bar. Five tabs is the limit, and Budget already has one filled Add.
- **No swipe as the only way to complete or delete.** NN/g says people do not find it. Add swipe only on top of a visible control, with Undo.
- **No progress rings or pie charts** for Budget. Ruled out in THE-PLAN section 9; bars already work.
- **No dynamic colour or per-section hues** on rows. Colour keeps its four meanings.
- **Do not remove the disclaimer notes** ("Estimate for FY2026-27, verify with a CA", "Rates as of"). Fold the dim sources line only.
- **Do not drop paise from EMI, tax or interest results.** Only whole-number amounts lose ".00" (B11).
- **Do not merge Due into To-do without the owner** (e3). It changes the tab list the owner already knows.
- **Unproven:** that a "Recent" strip on Tools helps (inference); that fewer Settings rows save taps (general guidance, untested here).
